# bots/ — 实战脚本

本目录存放可直接投入对局的完整脚本。**使用方式：复制文件全文 → 游戏内编辑器（TS 模式）粘贴 → 提交 → 开启辅助（Assist）。** 编辑器会把 TS 编译为 JS 再提交，`@omb/bot-api` 的类型由编辑器内置，无需额外配置。

## oracle.ts — Oracle（当前主力脚本）

单文件脚本：定向路线规划 + 线性血量权重 + 二阶提前量火控，并包含自动升级、短盾与局部躲弹。

### ① 路线规划（Orienteering / 定向问题）

把当前观察内的 `cores` / `uplinks` / `healthPacks` 统一抽象为带权节点（权重 = 得分值：Core +10、Mega +25、Uplink +15、主桩 +25、血包为效用折算分），每 0.5s 求解一次。资源、机器人与弹丸均按感知半径（普通 20m / 成功脉冲帧 32m）和视线遮挡裁剪，不是全图透视：

$$\max \; \sum_i v_i \;-\; \lambda \cdot \text{里程} \quad \text{s.t. 总里程} \le \text{MAX\_ROUTE\_M}$$

- **精确求解**：节点 ≤ 9 个时用 Held-Karp 状压 DP（`dp[mask][last]`），O(2ⁿ·n²) ≈ 4 万次转移；
- **超限预选**：当前观察的节点更多时按性价比 `value/(dist+8)` 预选 9 个再求解；
- **λ 汇率**：每多走 1 米需要 ≥ 0.25 分才值得绕路，是"路线尽量短、得分尽量高"的唯一旋钮；
- **站桩折算**：Uplink 需原地站 4s（240 tick），按 `UPLINK_STAND_COST_M=8` 折算为附加里程参与决策；
- 空路线（0 分）是合法基线；无路线时尝试局部 8m 探索方向，避开当前可见墙面与锁区，再交给 `navigateTo`，不是原地等待全图资源刷新。

执行层消费路线时：捡 Core / 压血包靠身体接触自动完成；Uplink 进入交互半径后转入站桩状态机（见下）。

### ② 血包线性权重

`v(hp) = K·(1 − hp/100)`，K=30：基础满血 100 时为 0，hp<67 压过 Core(+10)、hp<50 压过 Uplink(+15)。血包与得分目标在同一个 DP 里竞争，因此"顺路补血"会自然发生。当前仍按基础 100 HP 折算，未随血量升级后的 `maxHp` 归一化。

另有危急兜底：hp < 22 时无视路线直奔最近可用血包；站桩中血线告急会打断站桩。

### ③ 二阶提前量火控

目标运动按**恒加速度模型** `X(τ) = P + V·τ + ½A·τ²`：

- 加速度由相邻帧速度差分（÷1/60s）+ EMA（α=0.35）估计，幅度截断 30 m/s²（服务器普通加速度 24、dash 加速度 60，滤掉 dash/撞击尖峰）；速度 >8.5 m/s 时按匀速处理，这也可能包含移速升级后的普通移动；
- 拦截时间满足 `τ = τ₀ + |X(τ)−S|/v_b`（τ₀=1 tick 管线延迟，S 含自机速度前移），用**不动点迭代**解出（8 次，目标径向速度 < 弹速时收敛）；
- 开火闸门：命中点 ≤ 16.5m（散布从 16m 开始，并非全程无散布）、拦截时长 ≤ 1s、弹道未被当前可见墙面/锁区遮挡（Liang-Barsky 线段-AABB + 线段-圆检测）、能量 ≥ 15（近距除外）；
- 站桩期间只预瞄不开火（`canHack` 要求本 tick 无 fire 意图），近敌 ≤ 12m 才打断自卫。

### 关键机制适配（读 sim 源码得出）

| 机制 | 脚本对策 |
| --- | --- |
| Uplink 个人冷却 30s 不暴露给脚本 | 完成站桩时自跟踪 `uplinkCd`，冷却内不选该桩 |
| 中断后服务器保留进度（0.5s 宽限 + 每秒衰减） | `hackProgressMemory` 记忆进度，回坑时按衰减估计续跑 |
| 开火/交互会亲手打破 4s 重生保护 | 重生 240 tick 内保持不开火、不交互 |
| 锁区（半径 28m）挡子弹、锁 Core、封闭主桩 | OUTER_RING 剔除区内节点；弹道遮挡校验含锁区圆 |
| Core 重生会换位置，Mega 的价值由当前观察提供 | 节点读取 `core.value`（缺失时回退 10），不依赖旧 pad ID 白名单 |
| `navigateTo` 只依据当前观察导航，不掌握完整隐藏几何 | 持续根据新观察修正路线，不保证全局最短或路径可达 |
| 私密 `self.upgrade`（points/五轨 levels/bounty）与开局冻结 `game.upgradeCosts` | 成本当前 `[2,3,5,8,12,18,27,40,60,90]`；读 `costs[level]`、以长度判断满级，不硬编码；普通 Core +2 点、Mega +5 点，与计分分开 |
| `buyUpgrade(track): void` 只排队，结果以下一 tick 快照为准 | 多次调用累积，人类先、脚本后，共享 8 次/tick 上限；本帧自己预扣预算，不能循环等冻结快照更新 |
| 购买不参与分轴仲裁，也不破除复活无敌，死亡期间可买 | 点数不足/满级/热身静默无效；非法 track 抛 `TypeError`，异常/超时清空当 tick 脚本购买 |
| 赏金当前任一轨 ≥L4，阵亡散落钱包、可能掉 1 级 | 自己读服务端派生 `self.upgrade.bounty`，不要硬编码门槛；对手仅可由 `maxHp/maxEnergy` 推断对应轨，其他三轨不公开 |
| `obs.pointDrops` 按当前半径与视线裁剪，`nearestPointDrop()` 只搜索当前观察 | 环境晶片每只 1 点、赏金晶片每只 1–4 点，30s 过期、接触拾取谁碰归谁、只给技能点；无 TTL 字段，不探测隐藏或锁区内不可见晶片，不保证可达 |
| 每颗新增普通/Mega Core 附带最多 1/2 只环境晶片 | 全场环境存量上限 `ceil(参赛机器人席位数 / 4)`，含 bot、死亡者仍计席位；4/64/200/256 人分别为 1/16/50/64 只，满额只生 Core，额度不足只发可容纳的只数；拾取/过期腾额度后由后续新增 Core 补，不保证固定总收益 |
| 赏金晶片不占环境额度、不受其上限约束 | 赏金转移规则不变；Oracle 尚未把晶片列入 DP 路线节点，只会接触时顺带拾取 |
| 可见来弹威胁预测与防御 | 根据相对运动预测未来 0.45s 的接近威胁，忽略己方自身射出的弹丸；近撞且冷却/能量允许时申请短盾，较早威胁时侧移，能量 >25 且未开盾时尝试 dash；站桩时仍可短盾，不躲弹移动或 dash |

新增 API 的行为基准见[写第一个 Bot](../docs/manual/code/bot-scripting.md)。当前 `oracle.ts` 在每个存活 tick 按 **speed → hp → shield → attack → energy** 尝试购买，每轨每 tick 最多一级，按冻结成本表在本帧预扣预算；购买结果以下一 tick 为准。晶片仍未纳入 DP 路线。

脚本只获得可见墙面片段与 `arena` / `lock` 边界线段，`game.mapSeed` 恒为 `0`；浏览器用于地形绘制的完整静态引导包不扩展脚本、导航或实体感知。场上晶片视觉尺寸参数为 0.315m（由 0.42m 缩小 25%，保留最小像素尺寸），拾取/碰撞半径与 Core/Mega 美术不变。

### 验证状态

- `oracle.test.ts` 覆盖 DP、提前量、节点抽象与执行器状态机；`oracle-defense.test.ts` 覆盖 36m/s 来弹预测，以及忽略远离、自身射出和安全擦过的弹丸；
- 类型检查入口为 `tsc -p bots/tsconfig.json`（`@omb/bot-api` paths 映射）；编辑器 TS 编译、客户端清理与服务端 strip 后仍需保留顶层 `tick` 入口；
- 旧版站桩 479/480 tick 和 goja DP 耗时记录不作为当前实现的验证结论；当前站桩为 240 tick，测试与性能以本次完整验证为准。

### 已知取舍

- 节点 > 9 时预选是贪心近似（丢弃低性价比节点）；
- 里程用欧氏距离估算，墙体绕行会让实际路程略长；
- `CORE_ZONE_R=28` 与基础 100 HP 的血包权重仍为硬编码，规则或成长变化时需同步；
- 路线与防御只依据局部观察，不预知隐藏障碍或来弹；晶片尚无专门的路线收益模型。
