# 模块语义与陷阱

按主题拆解 Bot Script 的运行语义。每个主题：游戏怎么运行 → 什么时候用 → 陷阱在哪。逐 API 签名见[动作参考](actions.md)与[便利层参考](helpers.md)，逐字段见[数据结构](data.md)。

## 1. tick 生命周期

**怎么运行**：游戏以 60Hz（与模拟同频）调用你的 `tick(bot)`。一帧的标准流程：读感知 → 决策 → 调 API 表达意图。

- `ctx` 每帧重建：`self`、`game`、`scan()` 都是本帧快照，帧间不复用；
- **模块级状态跨帧存活**：写在 `const bot = {...}` 外面/里面的变量就是你的记忆（计数器、路标索引、自记冷却）。热更新成功后程序重建、状态清零；
- **每帧预算 10ms**：超时该帧脚本动作被清空（人的手操不受影响），下一帧照常恢复——是打断，不是禁赛；
- **一拍延迟**：第 T 帧读到的世界是 T 时刻的，产出的指令 T+1 帧才生效。所有"到点判定"留阈值。

示例库 `patrol.ts` 是本模块的标准教材——模块级状态加距离阈值：

```ts
let idx = 0 // 模块级状态：当前目标路标（写 tick 里就每帧清零了）

const bot = {
  tick(bot) {
    const me = bot.self.position
    const target = waypoints[idx]
    const dx = target.x - me.x
    const dy = target.y - me.y
    if (dx * dx + dy * dy < 4) {
      idx = (idx + 1) % waypoints.length // 距离 < 2m 算到点，切下一个
      return
    }
    bot.moveTo(target)
  },
}
```

**陷阱**：

- **别在 tick 里写阻塞循环**（比如"等到达再返回"的 while）：配额中断没有恢复点，该帧直接作废。tick 的正确姿势是"看一眼、决策、退出"，下帧再来；
- 状态声明在 `tick` 函数内部 = 每帧清零；要跨帧必须放模块级。

## 2. 感知

**怎么运行**：`bot.scan()` 返回游戏裁剪好的可见实体集合，零成本、每帧可读、每调给新对象。

- **可见性规则**（对机器人和弹丸）：中心距 ≤ 20m **且**视线不被墙拦截；
- **cores 与 uplinks 恒全量**：不受距离和墙限制，全图目标位置皆可知——这是全局导航（`nearestCore`/`nearestUplink`）的底气；
- **搭档豁免**：搭档恒在 `robots` 列表，无视距离与墙，带 `isPartner: true`；
- **自己不在 `robots` 里**（用 `bot.self`）；死者被过滤；
- **`pulseScan()`**：耗 12 能量、冷却 2s；执行成功的帧使用 32m 感知，普通帧仍为 20m，均受墙体遮挡。请求执行成功才扣能量和进入冷却，调用始终返回请求前已有的当前快照。

**陷阱**：

- 20m 外的敌人不可见 ≠ 不存在。贴墙走位减少暴露面；利用 cores/uplinks 恒全量做全局导航；
- 弹丸与机器人同规则裁剪——你**看到**弹丸时它可能已经在 20m 内飞了几帧了。侧移比硬吃划算。

## 3. 移动与战斗

**怎么运行**：`move` 表达期望速度方向、`aimAt` 定炮口、`fire` 发射；`moveTo` 是"朝点走"的糖。

- **`move(vx, vy)` 是期望速度向量**，不是位移：两个数合起来 ≤1 按比例走、>1 自动归一成满速。实际速度受加速度 24 m/s² 与限速 8 m/s 约束，起步和转向有惯性，没有瞬移；
- **开火节流是游戏强制的**：250ms 一发。脚本连点无效；能量不足 5 时安静地不打；
- **有效射程 16m，弹丸最大 20m**：超过 16m 弹道开始散布（最大 ±0.12 弧度），**伤害不衰减**（每发都是 12）。远距命中率靠距离换，伤害不打折也打不准；
- **开盾期间不能开火**：二选一。

**陷阱**：

- **轴锁存（全场最贵）**：`fire` / `dash` / `interact` 无参数，调用一次即锁存为"持续按住"，**没有 `fire(false)`**。锁存只能被三件事解除：死亡、脚本该帧异常/超时、玩家关辅助。后果按动作各不相同：
  - `fire()` 锁存 = 全自动射击（游戏 250ms 节流）；最终开火意图有效时无法黑入，脚本没有主动停止射击的参数；
  - `dash()` 锁存 = 电平触发：此后每逢冷却转好自动再冲、自动扣 20 能量；
  - `interact()` 锁存 = 持续按住（引导正需要）；出圈/开火断引导但按住状态保留，回圈自动续；
  - `move` / `aimAt` / `shield(on)` 同样保留最后值，但每帧重调即覆盖；shield 是唯一能主动传 `false` 关闭的动作；
- **开火意图与黑入互斥**：最终开火意图为 `true` 时不能引导，即使这一帧没有实际射击。脚本锁存需清空，或由玩家接管开火轴并停止开火，才可恢复引导；抢桩脚本应避免调用 `fire()`；
- **`aimAt` 同名两种用法**：传数字按角度、传机器人按实体。传**不可见**机器人当场抛异常 `aimAt: entity not visible`——先确认目标在 `scan().robots` 里（搭档不用确认）。

## 4. 目标交互

**怎么运行**：Core 走近自动捡（+10，Mega +25）；Uplink 要站桩引导黑入（+15，主桩 +25）。

- **Core**：走到机器人半径 0.6m 内自动拾取，**无需任何 API**。`nearestCore()` 给全图最近存活 Core——利用全局可见性规划顺路；
- **Uplink 黑入**：距桩 ≤2.5m（主桩 3m），持续引导 **8 秒**。期间每帧都要满足：存活、interact 按住、**未开火**、未出圈。中断则进度**清零重来**，不进冷却；
- **个人冷却 30 秒**：黑入成功后，**你**对这根桩 30s 内不能再黑。按机器人记、跨桩独立、**死亡不清**；
- **`nearestUplink()` 不含 ready/冷却信息**：它只给位置。桩的激活状态查 `scan().uplinks` 的 `ready`；你的个人冷却自记。

示例库 `uplink-rusher.ts` 演示减速站桩、计时和等待。成功事件不对脚本开放，所以这里只能估算；例子用全局等待简化了真实的逐桩冷却：

```ts
let cdUntil = -1 // 估算的等待截止时间（秒）
let started = -1 // 估算的引导起始时间，-1 = 未在计时

// ……（减速、刹车和离开范围时重置 started 见完整示例）
if (started >= 0 && bot.game.time - started > 8.5) {
  // 无法确认成功：仅按预计时长等待，服务器仍强制真实冷却
  cdUntil = bot.game.time + 30
  started = -1
}
```

**陷阱**：

- **fire 意图与黑入互斥**（同上节）：抢桩脚本应避免锁存 fire；
- 引导被打断的三大原因：fire 输出（含锁存残留）、被位移出圈、死亡。扛伤可以继续（挨打不断引导），但还手就断；
- 主桩在中央区，CORE_OPEN（4:00）才激活；`uplinks[i].ready` 是"桩激活且无人正在引导"，与你的个人冷却是两码事；
- **成功/失败不给脚本事件**：感知里没有"引导完成了"的字段。`game.time` 只能估算；即使多等半秒，也不能排除争抢、中断和手操接管导致的失败。

## 5. 存活

**怎么运行**：护盾减伤、dash 位移、能量是一切技能的货币（上限 100，回复 10/s）。

- **护盾**：受伤 ×0.35（减伤 65%）、耗能 18/s、移速 ×0.8、**不能开火**。每帧按"当前开关 + 能量"重新结算——能量见底那帧盾自动灭；死亡强制熄盾；复活重置；
- **dash**：耗 20、冷却 2.5s、持续 0.3s、冲刺速度 16 m/s（位移约 4.8m）、**无无敌帧**。方向取当前仲裁后的移动向量（零向量则用炮口朝向）；
- **能量经济**：忽略回复时，100 能量可支付 20 发子弹，或冲刺一次后再维持约 4.4 秒护盾。仅持续开盾时，回复抵消部分消耗，净耗能约 8/s；满能量冲刺后仍剩约 80，下一次冲刺主要受 2.5s 冷却限制；
- **复活**：死亡 3s 后于本扇区出生点重生，满血满能量带无敌。**无敌 4 秒从首次有效操作起算**（挂机一直无敌）；`fire` / `interact` 输出**立即**解除无敌。跨死亡保留：个人桩冷却、喊话冷却；清零：dash/脉冲冷却、**所有锁存轴**。玩家关闭辅助或脚本异常/超时也会清空脚本锁存。

示例库 `shield-brawler.ts` 是本模块的教材——低血开盾反向 dash 撤离：

```ts
const me = bot.self.position
if (bot.self.hp < 30 && bot.self.energy >= 20) {
  bot.shield(true)   // 开盾
  bot.move(me.x - enemy.position.x, me.y - enemy.position.y) // 反向推杆
  bot.dash()         // 调一次即锁存，撤离结束后仍可能自动再冲
  dashing = 1.5
  return
}
```

**陷阱**：

- dash 取当前仲裁后的 move 向量；未重新调用时可沿用旧方向，只有向量为零才取炮口方向；
- 复活保护从首次有效操作开始计时，瞄准、切换辅助、有效脚本指令等也会触发；并非只有移动才开始计时。fire/interact 输出立即解除保护。

## 6. 通信

**怎么运行**：`say(text)` 发全房间可见的公开文本（互信内网，无屏蔽）；`partner()` 拿搭档引用。

- **喊话 3 秒冷却，游戏强制**：冷却内的调用安静地丢掉（无错误、无事件）。没有长度截断——超长文本自己控制，别刷屏；
- **搭档恒可见**：返回本局固定搭档（未配对时为 `null`，先判空）。弹丸互免，感知恒在——是唯一可靠的"全图信标"；
- **没有队内频道**：与搭档的私密协作只能靠约定（比如"我在 3 号桩"）或双方脚本各自观测推理。

示例库 `partner-duo.ts` 演示发现敌人时喊话，自记 3.5 秒间隔：

```ts
let lastSay = -99 // 上次喊话时间（秒）

// 夹击时才喊，且至少隔 3.5 秒（游戏层还有 3s 强制冷却双保险）
if (bot.game.time - lastSay > 3.5) {
  bot.say('pincing ' + enemy.id)
  lastSay = bot.game.time
}
```

**陷阱**：

- `partner()` 可能为 `null`（未配对）——不判空直接用 `.position` 会当场抛异常；
- tick 里每帧喊话：冷却就绪时首条会发出，之后 180 帧内的调用被丢弃；自记间隔可减少重复请求；
- 喊话没有长度保护：超长文本全场可见地刷屏，社交后果自负。
