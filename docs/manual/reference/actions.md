# 动作参考（L0 原语）

L0 是 7 个最基础的动作：`move`、`aimAt`、`fire`、`dash`、`shield`、`interact`、`say`。一次调用只说一件事：这一帧我想做这个动作。组合动作（追踪敌人、找资源、脉冲扫描）在[便利层参考](helpers.md)。那层是 L0 的糖，最后还是落到这 7 个原语上。

所有动作守两条规则：

1. **调用只表达意图，结果由服务器裁定。** 脚本说"我要开火"，服务器检查冷却、能量、护盾状态，全部满足才真正发射。条件不满足就安静地不执行，不报错、不提示。判定全在服务器上，脚本里任何重试、绕过、抢跑的写法都改变不了结果。
2. **一帧可以同时表达多个动作。** 移动、瞄准、开火能组合；开盾会阻止射击，开火意图会阻止黑入。同一个动作在一帧内多次调用，以最后一次为准。

## 每 tick 显式意图

`tick(bot)` 里发出的调用只对下一次模拟 tick 有效。这一 tick 没调用的动作就是中立，不沿用上一 tick。脚本异常、超时或没跑完时，这一 tick 就没有动作。旧的 `bot.api.xxx()` 写法仍可用，但不会恢复旧的锁存语义。

想持续开火、冲刺、举盾或引导，就在条件成立的每个 tick 调用对应动作。想停，条件不成立时不调用就行。

两条边界要记牢：

- 炮塔朝向是机器人状态。不调用 `aimAt()`，炮口不会重置回零角度。
- 人类按键是独立的 held 状态。脚本省略动作，不会清掉玩家的按键。

## move(vx, vy)

**做什么**：告诉机器人往哪个方向走、使多大劲。它表达方向和期望速度，不是"走到某个点"。

| 参数 | 类型 | 含义 |
|---|---|---|
| `vx` | number | 世界坐标 x 方向的力度，正数朝右、负数朝左 |
| `vy` | number | 世界坐标 y 方向的力度 |

两个数合出任意方向：`(1, 0)` 满速向右，`(0, 1)` 满速朝另一根轴，`(0.7, 0.7)` 斜 45 度。两个数合起来超过 1，游戏自动归一成"满速朝这个方向"。

实际移动受两个物理量约束：加速度 24 m/s²、最大速度 8 m/s。起步和转向都有惯性，不能瞬间调头。

满速向右，每帧都要喊一次：

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  bot.move(1, 0) // 每帧都喊"向右满速"
}
```

追踪目标点时，把"我到目标的连线"直接当方向传：

```ts
const dx = target.position.x - bot.self.position.x
const dy = target.position.y - bot.self.position.y
bot.move(dx, dy) // 长度 >1 时归一为满速，否则按比例减速
```


**游戏规则**：`vx` 或 `vy` 不是正常数字（NaN、Infinity）时，这一帧你的脚本发出的所有动作全部作废。这是防作弊阀门，人的手操不受影响。

**常见坑**：

- 想走快点多传数：超过 1 一律归一成满速，"更快"的意图丢失。想满速就传归一后的方向，想减速就整体乘个小于 1 的系数。
- 期待急停急转：机器人有加速度惯性，提前几个身位反向推杆。

## aimAt(angle | target)

**做什么**：把炮塔转向指定方向。一个 API 名，两种用法，游戏按参数类型区分：

- 传**数字**：世界角度，单位弧度。半圈是 π ≈ 3.14，不是 180。
- 传**机器人**（RobotRef）：直接瞄它，不用自己算角度。这是 L1 便利层提供的重载。

两种用法：按角度瞄准，和按敌人实体瞄准。

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  bot.aimAt(Math.PI / 2) // 炮口转到 π/2 方向
  const enemy = bot.nearestEnemy()
  if (enemy) bot.aimAt(enemy) // 传实体：直接瞄它
}
```


**游戏规则**：

- 角度是 NaN 或 Infinity 时，该帧全部脚本动作作废，同 `move`。
- 实体用法只接受你看得见的机器人。瞄一个被墙挡住或超出视野的目标，脚本当场抛异常 `aimAt: entity not visible`。异常没接住，该帧全部脚本动作作废。

**常见坑**：

- 度数弧度混用：想转 90°，结果转了 90 弧度。全部用弧度。
- 对墙后的敌人用实体瞄准：先确认它在 `bot.scan().robots` 里。

## fire()

**做什么**：<img class="inline-icon" src="../reference/images/icons/fire.png" alt=""> 开炮。伤害 12 点，弹速 30 m/s，有效射程 16m。弹丸最远能飞 20m，但 16m 外精度开始下降，远距离是碰运气。

无参数。需要开火的每个 tick 都调用；某 tick 不调用，脚本开火意图就停了。游戏仍按 250ms 间隔节流。

**游戏规则**（以下任一条件不满足，这一炮安静地不发射，不报错）：

| 条件 | 数值 |
|---|---|
| 距上次发射 | ≥ 250ms（游戏替你节流，连点无效） |
| 能量 | ≥ 5（发射时扣除 5） |
| 护盾 | 关闭（开盾期间不能开火） |
| 状态 | 存活（死亡不能开火） |

**开火意图与黑入互斥**：本 tick 最终开火意图为 `true`，就不能黑入 Uplink，即使护盾、能量或节流让这一帧没有实际射击。抢桩分支不要调用 `fire()`。

看到敌人就转炮塔并保持全自动射击：

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  const enemy = bot.nearestEnemy()
  if (enemy) {
    bot.aimAt(enemy)
    bot.fire() // 条件成立的每个 tick 调用；游戏每 250ms 最多一发
  }
}
```


**常见坑**：

- 在同一个 tick 里反复调 `fire()` 想打快点：250ms 一发是硬上限，多调无效。
- 想停火时继续调用 `fire()`：是否实际射出不重要，开火意图本身就会阻止黑入。
- 抢桩分支忘记省略 `fire()`：该 tick 的引导会断。

## dash()

**做什么**：按住式冲刺，持续以 16 m/s 朝当前移动方向推进。用来赶路和拉开身位，不是无敌闪避。冲刺期间没有无敌帧，照样挨打。

数值：持续消耗 20 能量/秒；基础回复仍为 10/秒，单独长按时净耗约 10/秒。能量不足一 tick 消耗时自动停止，没有冷却。耗尽后要先释放再按下：脚本至少一个 tick 不调用 `dash()` 才能重新启动，避免靠回复逐帧启停。

**方向规则**：冲刺方向取当前仲裁后的移动向量。这个向量为零时，才朝当前炮塔方向冲。同一帧先 `move` 后 `dash` 还是反过来，结果一样。

**游戏规则**：每个希望持续冲刺的 tick 都要调用 `dash()`，省略即停。`shield(true)` 与冲刺同 tick 时护盾优先，服务器会停掉冲刺。

向后撤的同时触发冲刺，先给 move 方向再调 dash：

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  bot.move(-1, 0) // 这帧的移动方向 = 冲刺方向
  if (bot.self.hp < 30) bot.dash() // 残血期间每 tick 持续冲刺
}
```


**常见坑**：

- 只调 `dash()` 不提供移动方向：朝当前炮口方向冲。
- 把 `dash()` 写进无条件路径：持续耗能。只在确实需要冲刺的分支调用。
- 同 tick 同时开盾和冲刺：护盾优先，冲刺停止。

## shield(on)

**做什么**：护盾开关。开着时受到的伤害打 65% 折扣（只剩 35%），代价：每秒耗能 18、移动速度打八折、完全不能开火。

| 参数 | 类型 | 含义 |
|---|---|---|
| `on` | boolean | `true` 开盾，`false` 关盾 |

**游戏规则**：护盾每帧按"当前开关 + 剩余能量"重新结算。能量见底的那一帧盾自动熄灭；死亡强制熄盾；复活时重置。

建议每帧显式给值，比如 `bot.shield(bot.self.hp < 30)`。状态一目了然，也不会残留。它是唯一能传 `false` 主动关闭的动作。

条件开盾：血量低于 30 就举盾，否则省着能量。

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  bot.shield(bot.self.hp < 30)
}
```


**常见坑**：

- 开盾还想开火：互斥，两样只能选一样。近战缠斗时想清楚什么时候要输出、什么时候要保命。
- 只开不关：忘了 `shield(false)`，能量被慢慢耗干。用上面的条件写法就不会忘。

## interact()

**做什么**：<img class="inline-icon" src="../reference/images/icons/uplink.png" alt=""> 表达本 tick 的交互按住意图，引导黑入 Uplink（得分设备，玩家叫"桩"）。连续引导需要每个 tick 都调用。

**黑入流程**：站到桩周围 2.5m 内（中央主桩 3m），持续引导 8 秒完成，+15 分（主桩 +25）。

引导期间每一帧都要满足：活着、`interact` 按住、没有在开火、没出圈。

**中断规则**：松开、移出范围、开火、死亡会中断引导，但不会立刻清零。前 0.5 秒进度保持；仍未继续时，此后每 1 秒回退 0.5 秒进度，直到归零。挨打不打断。开盾硬顶引导是合法战术：对面打不断你，只能逼你开火或撤离，并争取让进度逐步回退。

**成功之后**：你个人对这根桩进入 30 秒冷却，期间不能再黑它。其他玩家不受影响，随时能来抢。冷却跨死亡保留。

逐步减速到桩旁，显式停止移动后持续引导：

```ts
import type { BotContext } from '@omb/bot-api'

function tick(bot: BotContext) {
  const uplink = bot.nearestUplink()
  if (!uplink) return
  const me = bot.self.position
  const dist = Math.hypot(uplink.x - me.x, uplink.y - me.y)
  if (dist > 1) {
    bot.move((uplink.x - me.x) / 3, (uplink.y - me.y) / 3)
  } else {
    bot.move(0, 0) // 刹车
    bot.interact() // 站桩期间每 tick 调用
  }
}
```


> 示例库 `uplink-rusher` 演示引导计时和等待策略，讲解在[模块语义与陷阱](modules.md)。脚本收不到成功事件，计时只是估算；争抢、中断和手操接管都可能让估算失准。

**游戏规则**：冷却中、距离不够、正在开火时，引导安静地不生效。个人冷却（30 秒）不下发给你：游戏不告诉你"还剩几秒"，要用 `game.time` 自己记。

**常见坑**：

- 引导到一半产生有效 `fire` 意图：引导立即中断；0.5 秒内停火并继续可保留进度，否则进度按每秒 0.5 秒逐步回退。
- 引导完成的瞬间又站桩硬等：这根桩对你已进入 30 秒冷却，等是白等。去下一个桩或抢 Core。
- 期待游戏提示"还差几秒完成"：进度圆环是手操 HUD 才有的，脚本侧只能自己计时。

## say(text)

**做什么**：发一条全房间广播的公开喊话。机器人头顶显示 4 秒像素气泡，气泡跟着机器人走。机器人不在视野内时，不会强行显示侧边消息。文本不设屏蔽，适合报点、调侃、约战术暗号。

| 参数 | 类型 | 含义 |
|---|---|---|
| `text` | string | 任意文本 |

**游戏规则**：冷却 3 秒，冷却中的调用安静地丢掉，无错误、无事件。文本先做归一化：空白和控制字符统一折算成空格；上限 160 个 Unicode 字符，超长截断，纯空白不发送。这 3 秒冷却与手操公开聊天共享同一个服务器冷却：任一端发过喊话，另一端也要等冷却结束。

发现敌人时喊话，自己记 3.5 秒间隔：

```ts
import type { BotContext } from '@omb/bot-api'

let lastSay = -99 // 上次喊话时间（秒）

function tick(bot: BotContext) {
  const enemy = bot.nearestEnemy()
  if (enemy && bot.game.time - lastSay > 3.5) {
    bot.say('enemies near core ' + enemy.id)
    lastSay = bot.game.time
  }
}
```


**常见坑**：

- 在 tick 里每帧喊：冷却就绪时第一条会发出，此后 3 秒内的调用被丢弃。自己留 3 秒以上的间隔即可节流。
- 把 `say` 当队内频道：这是全场公开喊话，所有人都能看到。
