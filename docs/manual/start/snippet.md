# Snippet 驾驶辅助

Snippet 是无需从零写代码的官方驾驶辅助。它们不是绕过规则的外挂：每条都是服务器提供、可以查看源码的 Bot Script 模块，与玩家代码在同一个 Goja 运行时、同一帧预算和同一套分轴仲裁中执行。

在对局侧栏点击 **辅助** 打开面板，勾选模块、调整参数后点击 **应用配置**。服务器会校验整份配置并重新组合脚本；参数非法或组合失败时，现役配置和脚本保持不变。配置草稿按房间码和昵称保存在当前浏览器，服务器回执才代表已经生效。

## 八条官方模块

| Snippet | 行为 | 参数 |
|---|---|---|
| 自动瞄准 | 炮塔锁定最近可见敌人 | 是否按目标速度计算提前量 |
| 自动开火 | 敌人在阈值内时瞄准并开火 | 射程阈值（2–20m） |
| 自动拾取 | 直线移向半径内最近的 Core 或可用血包 | 拾取半径（0.5–20m） |
| 紧急护盾 | HP 低于阈值时举盾，恢复后关闭 | HP 阈值（0–100） |
| 危险规避 | 敌人或炮弹进入威胁范围时向安全方向移动 | 威胁半径（2–20m） |
| 简单巡逻 | 按顺序直线移动到路径点 | `x,y;x,y`，最多 8 点，坐标范围 ±80m |
| 全局 Core 拾取 | 用 `navigateTo` 前往全图最近存活 Core；目标被抢后自动重选 | 无 |
| 低血量自动拾取血包 | HP 低于阈值时，用 `navigateTo` 前往最近可用血包 | HP 阈值（0–100） |

每条模块都可展开 **查看源码**。展示的源码来自当前服务器的官方目录，与实际组合执行使用同一定稿；复制源码只会进入剪贴板，不会覆盖编辑器草稿。资源都靠机器人移动接触自动拾取，Bot API 没有 `pickup()`。

`moveTo` 是直线移动；`navigateTo` 是服务器确定性的静态 A*，避开实体墙、竞技场边界和尚未解锁的中央区；它不执行动态机器人避障、威胁评估或弹道预测。导航类模块使用 `navigateTo`，非导航模块仍按各自源码使用直线移动或其他策略。

## 与玩家代码如何组合

每个 tick 先执行玩家代码，再按固定目录顺序执行启用的 Snippet。玩家代码本 tick 已操作的轴不会被 Snippet 覆盖；未操作的轴仍可由 Snippet 控制。例如玩家代码负责移动，自动瞄准仍可接管炮塔。没有玩家代码时，Snippet 也可以单独运行。

服务器对移动、炮塔、开火、技能四根轴分别记录来源。最终采用 Snippet 的轴会显示为 Snippet 来源，并计入“古法编程”称号的判定；仅勾选但没有实际产生控制，不计使用。

## 总开关与人工接管

配置模块后，还要开启驾驶辅助总开关：

- 编辑器中的 **辅助 ON/OFF**；
- 战场画布聚焦时按 `Space`；
- `Numpad Enter`（小键盘回车）是无冲突备用键，普通 `Enter` 仍用于聊天。

辅助关闭时程序动作不会生效。辅助开启后，人的输入仍按轴即时优先；被抢占的轴不会因为松手自动交还，再按一次总开关即可交还人工轴。完整规则见[操作与控制仲裁](../rules/controls.md)。

## 配置保存与换局

Snippet 配置保存在房间的玩家身份上：短暂断线重连、热身进入正式局和房主重开时会重新应用。显式离开房间释放身份后，服务器配置随之清除；浏览器里的草稿仍保留，下一次可重新应用。
