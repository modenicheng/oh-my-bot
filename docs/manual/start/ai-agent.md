# AI Agent

对局侧栏的 **AI** 面板可以用自然语言修改当前玩家的 Bot Script。输入具体要求并发送后，服务器把当前玩家源码和面向 AI 的手册章节交给已配置的模型；返回的新脚本通过普通 Hot Swap 链路编译、加载并立即生效。

AI 只读取和修改发起请求者的源码，不能访问其他玩家代码，也不能绕过 Bot API、感知范围、脚本帧预算或控制仲裁。模型密钥仅保存在服务器的进程环境或 `.env`，不会下发客户端、写入对局事件或出现在错误提示中。

## 使用步骤

1. 进入热身或正式对局，打开侧栏 **AI**。
2. 写清楚希望修改的行为，例如“HP 低于 35 时停止开火并远离最近敌人”。
3. 点击 **发送**。同一玩家一次只处理一个请求，完成前按钮会锁定。
4. 面板显示模型说明、错误和剩余配额。脚本编译成功后自动热更；编译失败或版本冲突时旧脚本继续运行。
5. 需要程序动作生效时，确认驾驶辅助总开关已开启。

协议目前不回传 AI 生成的完整源码，因此热更成功后**不会自动覆盖浏览器里的编辑器草稿**。面板会明确提示这一点；继续手动编辑前，请根据实际效果决定如何同步本地草稿。

## 默认配额

| 额度 | 默认值 |
|---|---|
| 每人每局提示轮次 | 20 轮 |
| 每人每局 token | 300k |
| 单局全场 token 护栏 | 2M |
| 全局并发 | 20 个请求 |
| 同一玩家并发 | 1 个请求 |

一次玩家提示占一轮；token 按上游 `usage` 返回的实际用量记账。热身与紧接其后的正式局共享同一额度，新一轮热身或从空闲直接开新局时重置。全局护栏触顶后，本局所有玩家都不能继续调用 AI。

## 热更与并发安全

AI 请求期间仍可手动提交代码。服务器在请求开始时记录脚本版本，模型返回后只在版本仍相同时落地；如果玩家已手动热更或另一结果先到，迟到的 AI 脚本会被丢弃，不覆盖新版本。模型调用在房间锁外执行，不会因为等待网络而阻塞 60Hz 对局。

Snippet 与 AI 可以同时使用。AI 只修改玩家源码，官方 Snippet wrapper 不会出现在模型看到的代码里；AI 脚本落地后，服务器会继续与现役 Snippet 配置重新组合。

## 部署者未启用时

如果服务器未启用 AI，面板会返回定向提示，不会把指令广播到聊天。部署者需要在 `config.yaml` 开启 `ai.enabled`，并在同目录 `.env` 或进程环境中设置 `DEEPSEEK_API_KEY`；配置方式见[部署指南](../../deploy.md)。

动作接口、持续意图和脚本预算见[写第一个 Bot](../code/bot-scripting.md)与[API 总览](../reference/index.md)。无需写代码时，也可以直接使用[Snippet 驾驶辅助](snippet.md)。
