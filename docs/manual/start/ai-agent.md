# AI Agent（接入状态与规划）

AI Agent 的目标是让玩家用自然语言修改自己的 Bot Script。**当前客户端尚无 AI 对话面板，房间服务收到 AI 请求时仍返回 `not configured` 占位提示。** 单独设置 `DEEPSEEK_API_KEY` 不能启用游戏内改码。

## 已有组件与待接入部分

仓库已实现 DeepSeek 调用、配额记账和脚本改码组件，并有各自的测试。仍需将这些组件接到房间生命周期、当前脚本与感知数据，并提供客户端入口，才能形成完整的玩家操作流程。

规划中的权限边界是：Agent 只读取和修改当前玩家自己的代码，使用该机器人的感知数据；模型密钥由部署者管理。

## 配额组件的默认规则

以下数值已在配额组件实现，**当前房间请求尚未使用它们**：

| 额度 | 默认值 |
|---|---|
| 每人每局提示轮次 | 20 轮 |
| 每人每局 token | 300k |
| 单局全场 token | 2M |
| 全局并发 | 20 个请求 |
| 同一玩家并发 | 1 个请求 |

一次玩家提示占一轮，轮次预留后失败不退；token 按模型返回的实际用量记账。配额设计要求热身与正式局共池、下一局重置，房间接入时还需实现这些生命周期调用。

## 准备改码需求

即使通过外部工具生成脚本，也应给出具体规则，例如“血量低于 30 时撤退”。动作限制见[API 总览](../reference/index.md)：所有脚本动作都是每 tick 意图，条件成立时要持续调用，条件不成立时省略即可停止。

脚本接口加载失败时保留旧版本；已成功加载的新脚本在某帧异常或超时，会清空脚本动作，不会自动回滚旧版本。提交语法和运行预算见[写第一个 Bot](../code/bot-scripting.md)。
