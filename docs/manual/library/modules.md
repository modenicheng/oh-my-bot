# 模块语义与陷阱

按功能域拆解 Bot Script 的运行语义。每个模块：职责 → 何时用 → 陷阱。API 逐条签名见 [api.md](api.md)。

## 1. tick 生命周期

**职责**：服务器以 60Hz 与模拟同频调用你的 `tick(ctx)`，一帧 = 读取感知 → 决策 → 调 API 表达意图。

- **TickContext 每帧重建**：`ctx.self`、`ctx.game`、`ctx.scan()` 都是本帧快照，帧间不复用；
- **模块级状态跨帧存活**：`const bot = {...}` 外面/里面声明的变量就是你的记忆（计数器、路标索引、自记 CD）。Hot Swap 成功后 VM 重建、状态清零；
- **配额**：单 tick 默认 10ms，超时该 tick 脚本轴被清空（人类轴不受影响），下一 tick 恢复执行——不是禁赛；
- **一拍延迟**：tick T 读到的是 T 时刻世界，产出的命令在 T+1 消费。所有「到点判定」留阈值（如 `dist < 2` 而非 `== 0`）。

**陷阱**：
- 每帧重算而不缓存扫描结果可以，但**不要在 tick 内做阻塞循环**——配额中断没有恢复点；
- 状态写在 `tick` 局部 = 每帧清零；要跨帧必须放模块级。

## 2. 感知

**职责**：`ctx.scan()` 返回服务器裁剪好的可见实体集合，零成本、每帧可读。

- **可见性规则**（对其他机器人/弹丸）：中心距 ≤ 20m 且视线不被墙拦截。**cores 与 uplinks 恒全量**——不受距离与墙限制，全图目标皆可知位置；
- **Partner 豁免**：搭档恒在 `robots` 列表，无视距离与墙；`isPartner: true` 标记；
- **自己不在 `robots` 里**（用 `ctx.self`）；已死亡机器人被过滤；
- **`pulseScan()`**：耗 12 能量、CD 2s。**v1 当前实现：脚本观测管线视野硬编码 20m，脉冲的 32m 扩视野尚未接入脚本侧**（设计意图为 32m，仍不穿墙）。调用仍消耗能量并计 CD，返回与 `scan()` 同源的本帧快照。

**陷阱**：
- 20m 外的敌人不可见 ≠ 不存在。靠墙走、利用 cores/uplinks 全量可见做全局导航；
- 弹丸也受同样裁剪——看到弹丸时它可能已在 20m 内飞了若干 tick，侧移而非硬吃。

## 3. 移动与战斗

**职责**：`move` 表达期望速度方向、`aimAt` 定炮口、`fire` 发射；`moveTo` 是「朝点走」的糖。

- **`move(vx, vy)` 是期望速度向量**，非位移：幅值 ≤1 时按比例、>1 归一。实际速度受加速度（24 m/s²）与限速（8 m/s）约束，不会瞬间转向；
- **`fire()` 节流由服务器强制**：250ms 间隔（FireInterval=15 tick）。脚本连点无效，能量不足 5 时静默不发射；
- **有效射程 16m，最大 20m**：超过 16m 弹道开始散布（最大 ±0.12 rad），伤害不衰减（12 点/发）。散布是距离函数——远距命中率靠距离换；
- **开火时不能开盾**：`ShieldOn` 期间 `fire` 被门控，二选一。

**陷阱**：
- **轴锁存（最贵）**：L0 的 `fire/dash/interact` 无参数，调用即置 true 并**锁存**——没有 `fire(false)`。锁存只能被三件事清除：死亡、脚本 tick 异常/超时（清轴）、玩家关辅助。后果按轴不同：
  - `fire()` 锁存 = 全自动射击（服务器 250ms 节流），且 **与 hack 永久互斥**（见 §4）——v1 无法点射；
  - `dash()` 锁存 = 电平触发：此后每逢 2.5s CD 到期自动再冲一次（每次耗 20 能量）；
  - `interact()` 锁存 = 持续按住（引导正需要）；出圈/开火自动断引导，但按住状态保留，回到圈内自动续引导；
  - `move/aimAt/shield(on)` 同样锁存最后值，但每帧重调即可覆盖；shield 是唯一能传 false 主动关掉的轴；
- **fire 与 hack 互斥**：canHack 要求本 tick `!Output.Fire`。只要锁存过 `fire()`，就再也无法黑桩（直到死亡重置）。分工型 bot（farmer/rusher）从源头上别碰另一个功能的 API；
- **L0 `aimAt(angle)` 与 L1 `aimAt(target)` 同名重载**：传数字按角度、传 RobotRef 按实体。传了不可见实体抛 `aimAt: entity not visible`——先确认目标在 `scan().robots` 里。

## 4. 目标交互

**职责**：Core 触碰即拾取（+10，Mega +25）；Uplink 需站桩引导黑入（+15，主桩 +25）。

- **Core**：走到机器人半径内（0.6m）自动拾取，无需 API。`nearestCore()` 返回全图最近存活 Core——利用全局可见性规划顺路；
- **Uplink 黑入**：距桩 ≤2.5m（主桩 3m）持续引导 **8 秒**，期间每 tick 都要满足：存活、`interact` 按住、**未同时 `fire`**、未出圈。中断（松手/开火/死亡/被推出圈）则进度**清零重来**，但不进 CD；
- **个人 CD 30s**：黑入成功后，**你**在这根桩 30s 内不能再黑。CD 按机器人记，跨桩独立、死亡不清（Combat 重置时 SayReady 保留、ReadyAt 在桩上）；
- **`nearestUplink()` 不含 ready/CD 信息**——它只给位置。判断「这桩我能不能黑」自己记 CD（见 [examples/uplink-rusher.ts](examples/uplink-rusher.ts)）。

**陷阱**：
- **fire 锁存与 hack 永久互斥**：canHack 要求本 tick `!Output.Fire`。只要脚本曾调过 `fire()`（锁存），就再也属不上任何桩——直到死亡重置或玩家关辅助。rusher 型 bot 绝不调 fire；
- 引导被打断的三大原因：fire 输出（含锁存残留）、被击退/位移出圈、死亡。扛伤可以继续（受伤不打断），但还手就断；
- 主桩在中央区，CORE_OPEN（4:00）阶段才激活；`uplinks[i].ready` 是「桩激活且无人持有进度」，你的个人 CD 另算；
- 成功/失败事件不下发给脚本（Observation 无成功字段），引导时长与 CD 需自己用 `game.time` 记（见 [examples/uplink-rusher.ts](examples/uplink-rusher.ts)）。

## 5. 存活

**职责**：护盾减伤、dash 位移、能量是一切技能的货币（回复 10/s，上限 100）。

- **护盾**：开启期间受伤 ×0.35（即 -65%），耗能 18/s，能量耗尽自动熄火。开盾移速 ×0.8、**不能开火**。每 tick 依据「当前输入 + 能量」重算——能量见底那帧盾就灭；
- **dash**：耗 20 能量、CD 2.5s、持续 0.3s、冲刺速度 16 m/s（位移 ≈4.8m）、无无敌帧。方向 = 本 tick 的 `move` 向量（零向量则用当前炮口朝向）；
- **能量经济**：满能量 100 = 5 发子弹或 1 次 dash + 5.5s 护盾。回复 10/s 意味着 dash 后 2s 内开不出第二段。规划连招顺序（先盾后 dash 会发现两样都开不出）；
- **复活**：死亡 3s 后于出生点重生，满血满能量带无敌。**4s 计时从首次有效操作才开始**（静止不动则一直无敌）；`fire`/`interact` 输出立即解除无敌。跨死亡保留：个人桩 CD、say CD；清零：dash/pulse CD、所有锁存轴（这也是解除 fire 锁存的唯一自救手段）。

**陷阱**：
- dash 方向取 move 向量——同 tick 内先 `move` 再 `dash`（顺序无关）即可控向；只调 dash 不调 move 时朝炮口方向冲（可能正冲向敌人）；
- 无敌是「静止才有」：复活后一动就启动 4s 倒计时，fire/interact 则立即解除。想白嫖无敌就别动。

## 6. 通信

**职责**：`say(text)` 发全房间可见文本（互信群体），`partner()` 拿搭档引用。

- **say 3s 冷却，服务器侧强制**：CD 内调用静默丢弃（无错误、无事件）。运行时纯透传——别在 tick 里每帧 say，浪费且无效；
- **`partner()` 恒可见**：返回本局固定搭档（奇数局末位玩家为 `null`）。搭档不可被你伤害（弹丸豁免），恒在感知里——是唯一可靠的「全图信标」；
- 无队内频道 API：与搭档协作只能靠约定（如「我在桩 3」）或双方脚本各自观测推理。

**陷阱**：
- `partner()` 可能为 `null`（奇数局末位）——先判空再用；
- say 无长度截断提示，长文本自行控制（事件直发，超长影响他人阅读）。
