# 升级玩法（技能点系统）

设计已与用户对齐（2026-10-15，资源供给口径于 2026-10-16 修订）。经济循环：拾取 core → 技能点（黄色菱形）→ 按 1-5 键购买五维升级；任一轨达 L4 进入赏金状态，阵亡散落点数晶片（PointDrop，新实体，非 core），形成击杀回报循环。本计划数值表为 design of record，ADR-0016 修订 ADR-0003。

## 口径（已拍板）

- 普通 core（价值 10）= 2 技能点，中央 Mega（价值 25）= 5 技能点；每颗新增普通/Mega core 附带最多 1/2 只各 1 点环境晶片，还受全场人数存量上限约束，不保证固定总收益，也不再守恒旧 5/10 SP 预算。core 计分语义不变，技能点是平行货币。
- 全场环境晶片存量上限为 `ceil(参赛机器人席位数 / 4)`（含 bot、死亡者仍计席位）：4/64/200/256 人分别最多 1/16/50/64 只。只使用剩余额度，满额时只生 core；拾取或 30s 过期释放额度，后续新增 core 才补充，不立即补货。赏金晶片不占环境额度、不受该上限约束，赏金规则不变。
- core 每次补货在所属外/中/中央环带重新随机选坐标，不再回到固定 pad。环境晶片分散在同环带，不围着 core 成团；资源间距至少 2m，避墙、边界、未开放锁区、机器人脚下、Uplink 交互区与血包。血包位置与冷却不变。未拾取的 core 不搬家、不重复发放晶片；晶片 30s 到期，只有下次新增 core 才分配新预算。
- build 私密：等级/点数走 SelfState 仅本人可见；RobotState 只公开 maxHp/maxEnergy（头顶条分母，满血条变长属天然泄露）。
- 局内成长：开局清零、死亡保留（除赏金惩罚）、复活按当前上限满状态；买血量轨顺带回血 +增量；死亡期间可购买；仅 Running 可买（Warmup/Ended/观战拒绝，暂停自然冻结）。无 respec、无跨局继承。

每级成本 **[2, 3, 5, 8, 12, 18, 27, 40, 60, 90]**，单轨累计 265，全树 1325。

边际效率（血量轨 HP/点）：L1 10 → L5 1.7 → L10 0.11；强递减鼓励前中期广撒、后期才谈专精。

### 五维成长（满级 10，L6 起效益减半）

| 轨 | L1–5 每级 | L5 | L6–10 每级 | L10 | 说明 |
|---|---|---|---|---|---|
| 血量 | +20（顺带回血） | 200 | +10 | 250 | |
| 移速 | +0.4 m/s | 10.0 | +0.2 | 11.0 | Dash 15 m/s 不变 |
| 盾量 | 承伤系数 −0.05 | 0.10 | −0.01 | 0.05 | 盾下承伤 12.6→3.6→1.7 DPS（对基础火力） |
| 攻击 | +1.0 | 14 | +0.5 | 16.5 | DPS 36→56→66；射速/弹速不动 |
| 能量 | +25 | 225 | +15 | 300 | 回复恒 10/s（到 20/s 会与开火耗能 20/s 打平=无限火力，故不动） |

TTK 验算（持续火力无盾）：基线 2.8s；攻5→基础 1.8s；攻5→血5 3.6s；攻10→血10 250/66=3.8s（满对满仅 +35%）；攻10 vs 血10+盾10 名义 75.8s 但盾 uptime≤300/18=16.7s 且开盾禁火=脱离窗口非无敌；能10+攻10 倾泻 60 发=990 潜伤（15s），耗尽后回落 2 发/s=33 DPS。

### 阵亡惩罚（赏金机制）

- 赏金状态：任一轨 ≥L4 即触发；基准 = 等级最高轨的下一级成本（满级取其当前级成本 90）。
- 情形 A（自由点数 ≥ 基准×50%）：只散落全部自由点数。
- 情形 B（自由点数 < 基准×50%）：散落 自由点数 + 等级最高轨掉 1 级（该级购入成本全额转化为掉落点数；平级按 hp→speed→shield→attack→energy 取先）。
- 掉落物 PointDrop（技能点晶片）：总量 T 拆 k=clamp(max(ceil(T/4), rand(6..12)), 1, T) 只（赏金晶片仍每只 1–4 点，独立于环境晶片的固定 1 点；2026-10-15 调整，原为 ≤4 只、每只约 15 点）、余数摊给前几只；死亡点周围 1–4m 确定性 RNG 散布（避墙钳制）；30s（1800 tick）未拾取消失；接触拾取、谁碰归谁（含复活本人）；只给点数不给计分；锁区内遵循锁区限制；死因不影响；掉轨后若无一轨 ≥L4 则脱离赏金（棘轮自平衡）；单次最多掉 1 级、等级永不跌破 L3 以下。

### 合理性评估结论

- 惩罚与反制形成真决策：囤点→死丢钱包；花光→死掉级。风险随 build 深度自动放大（L7 轨门槛 20 点、L9 轨 30 点）。
- 零守恒破坏：掉级退款=地面点数，纯转移无通胀；无刷点漏洞（只掉自己存量）。
- 棘轮效应：掉到 L3 即退出赏金；新手期（单轨 <18 点）完全无惩罚。
- 已接受风险：早期专精流刚买 L4 就死会掉回 L3（损失 8 点；旧模型约为 1 分钟收入，现版本耗时待实测），实装后观察前 3 分钟弃局率再定是否把门槛升到 L5；连杀收割滚雪球由「击杀者自身很快进赏金态」对冲，压测期观察击杀榜与点数分布。

## Bot Script API 升级面（v2 补齐）

撤销原 v1 对 bot-api 升级能力的排除：脚本通过 `buyUpgrade(track): void` 购买，`nearestPointDrop(): PointDropRef | null` 找当前观察里最近的存活晶片；类型由 `packages/bot-api/src/index.ts` 单源生成服务器 AI 语料和客户端补全。`self.upgrade` 仅本人可见（points/五轨 levels/服务端派生 bounty），可见对手只公开 `RobotRef.maxHp/maxEnergy`，不泄露 shield/attack/speed 等级。

`game.upgradeCosts` 是开局冻结的只读成本数组，当前 `[2, 3, 5, 8, 12, 18, 27, 40, 60, 90]`；索引 L 是 L→L+1 价格、长度即满级。`self.upgrade`/levels、成本数组、`obs.pointDrops` 数组及晶片对象只读冻结，购买结果以下一 tick 快照为准。赏金当前任一轨 ≥L4，但脚本应读服务端派生的 `bounty` 而非硬编码门槛。

购买仍走 collector → `ScriptCommands.Upgrades` → `ApplyScriptCommands` 克隆至 `PendingScript` → `consumeInputs` 在死亡分支前追加 `PendingUpgrades` → 按序校验扣点 → `ControlRecord.Upgrades` 回放。人类先、脚本后，共享每 tick 8 次上限；多次调用累积，超出丢弃；点数不足/满级/热身静默无效，非法 track 抛 `TypeError`。死亡可买，不参与分轴仲裁、不破除复活无敌；异常/超时清空当 tick 脚本购买，热身由 glue 剥离购买队列。

`obs.pointDrops` 与 `scan()` / `pulseScan()` 同享当前观察，和机器人、弹丸、Core、Uplink、血包一样受当前半径（普通 20m / 脉冲帧 32m）及视线遮挡裁剪。环境晶片每只 1 点、赏金晶片每只 1–4 点，生成 30s 后过期，只给技能点，接触拾取谁碰归谁（含复活本人）。`nearestPointDrop()` 只搜索当前观察；离开视野不等于被拾取，锁区未开放时也不会透视其中的晶片。无 TTL 字段，首次看到不等于生成时刻。

浏览器可靠引导包仍可携带完整静态地形供稳定渲染与相机定位，但客户端实体、HUD、反馈必须使用局部观察；脚本导航和 AI 感知不能借此获取隐藏地图。脚本 `game.mapSeed` 已弃用且恒为 `0`，`obs.walls` 只提供当前可见墙面片段（可为零厚度 AABB，id 仅当帧有效），`obs.boundaries` 只提供可见 `arena` / `lock` 表面线段。观战与离线回放保持独立全知数据流。行为基准见[写第一个 Bot](../manual/code/bot-scripting.md)，完整设计见[Bot API 升级面](bot-api-upgrade.md)。
