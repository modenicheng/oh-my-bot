# 全部模拟相关节奏统一 60Hz 单时钟

模拟步长、Bot Script tick、Observation 计算与网络快照全部对齐 60Hz，共用一个时钟。放弃了解耦频率（如脚本/快照 20Hz）的 CPU 与带宽节约方案：单时钟消除全部频率对齐类 bug，脚本以模拟原生分辨率思考，客户端无需插值多套节奏。带宽用增量编码与 AOI 裁剪控制。脚本配额：单 tick 默认预算 10ms（可配置），超时由 goja interrupt 强制中断、该 tick 机器人 idle 并计入统计。配额是防死循环与滥用的正确性机制，非性能预算——典型脚本远低于此值，上限只约束退化代码的最坏占用。

## 修订（2026-09-29，复审 D5）：脚本并行与整帧预算

- **并行执行**：每 tick 脚本在 worker 池中并行运行（goroutine/进程隔离，非串行），64 脚本不共享单帧预算。
- **运行时抽象**：并行层不绑死 goja——ScriptRuntime 接口抽象，为后期接入 Python/C++/Java 运行时预留（进程隔离、通信协议中立）。v1 实现：goja（JS/TS）单运行时。
- **整帧截止 12ms**：模拟+感知+脚本+快照必须在 12ms 内完成，剩余为安全余量。
- **超帧降级**：截止前未完成的脚本顺延至下 tick 并计一次 idle（不计异常），不阻塞帧。
- **压测门槛**：64 台满配额（10ms）脚本并行 < 12ms 整帧，达不到则降单脚本预算。
