# 对局事件溯源：模拟只产事件，统计皆投影

权威模拟主循环不内置任何统计/结算逻辑，只向追加式 Match Event Log 写入状态变迁事件（输入、命中、拾取、引导完成、转段、热更新、死亡……）。称号结算、赛后统计页、回放与平衡性分析全部作为事件流的投影消费方实现。放弃了内联计数器+事后补日志的方案：事后补事件等于重写模拟器插桩，且新增统计指标无法回溯历史对局。

## 修订（2026-09-29，复审 D4）

原决策不变，补充可执行契约：

- **持久化格式**：JSONL，每局一文件（`data/matches/<match_id>.jsonl`），首行声明 `schema_version`，随后 `match_start` 记录保存 tick 0 状态、地图种子与地图定义。新日志的 `players` 表保存机器人 ID、持久玩家 ID、昵称、搭档 ID 和测试 Bot 标志；旧日志可通过外部身份表补全投影。
- **回放检查点**：每 60s 追加一份全量状态快照事件，回放器从最近检查点重建；确认整份日志连续性后，需逐 tick 模拟的区间最多 60s。校验需读取整份日志，不等于整个恢复过程只处理 60s 的记录。
- **线上事件 ≠ 完整日志**：omb.proto ServerEvent 是日志的投影子集（带宽裁剪）；完整日志含 EvMatchStart/EvWallHit/EvScriptError 等全部埋点。
- **新增埋点**：EvMatchStart（地图种子）、EvWallHit（0.5s/robot 节流，铁头娃）、EvScriptError（人工智障，含 script_rev）。

依据：docs/design/reviews/2026-09-29-gpt6-astra-audit.md 发现 #5。

## 模拟版本（2026-10-01）

`match_start` 与检查点的 `state.simulation_version` 区分物理语义，不能仅靠地图生成版本判断。字段缺省或为 `0` 的历史状态沿用机器人间仅位置分离的行为；版本 `1` 增加有上限、会衰减的接触冲量。恢复状态时必须同时恢复此版本，日志读写拒绝未知版本，避免用新物理静默重演旧录像。JSONL 结构版本仍为 `1`。

这项版本标记不等于客户端已进行逐 tick 物理重演：当前录像画面仍是检查点与事件投影，不能据此宣称具有每帧物理精度。

## 身份与终局记录

服务端重演消费记录的 `input` 与 `control`，不重新调用脚本运行时或外部模型。控制记录涵盖脚本动作、assist、脚本轴清除和手动发言；内置测试 Bot 使用相同通道。初始状态与 60 秒检查点恢复地图、模拟版本和所有机器人控制状态。生产入口 `sim.RestoreCheckpoint` 与 `sim.ReplayTo` 不启动时钟或脚本运行时，返回由调用方逐 tick 驱动的模拟器。`ReplayTo` 会验证整份已读记录的身份、地图、物理版本和输入序列，再选取不晚于目标 tick 的最近检查点；检查点不能掩盖前段未知机器人或倒退的输入序号。恢复同时拒绝阶段与 tick 不符、不可写的 Uplink 冷却表等异常状态。此验证不是日志签名或逐检查点内容真实性证明。

模拟器在终局 tick 先发结束标记，再发最后一个检查点。glue 层在投影该检查点后关闭生存段、计算分数和称号，然后将带真实机器人 ID 的 `match_end` 写入日志并可靠广播一次。这样 `RUNNER` 包含最后 60 秒的检查点距离，文件末尾的计分与在线广播一致；模拟器本身不承担计分。

`TestWholeMatchReplayFromInitialAndMidpoint` 覆盖完整 28800 tick，从 tick 0 和 14400 检查点比较终局状态与事件序列。glue 的整场测试另行比较持久身份、最终检查点、计分投影与终局广播；内置 Bot 测试验证实际运行时产生的控制日志可重演。客户端录像仍采用检查点加事件的近似画面，不是上述服务端逐 tick 重演器的浏览器实现。
