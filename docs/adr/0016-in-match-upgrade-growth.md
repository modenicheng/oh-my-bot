# ADR-0016：局内升级成长（修订 ADR-0003 的边界）

## 背景

ADR-0003 裁定「一局内基础规则不变」，放弃了 v0.1 的多阶段变规则方案。升级玩法（docs/plans/upgrade-system.md）让玩家在局内用 core 换技能点、购买五维升级（血量/移速/盾量/攻击/能量，满级 10），并在阵亡时受赏金惩罚——这与「规则全程不变」的字面裁决冲突，需要明确新边界。

## 裁决

1. **ADR-0003 的「不变」收缩为：基础规则与成长曲线在开局时冻结。** 机体基础数值（100 HP、8 m/s、伤害 9 等）、升级成本表 [2,3,5,8,12,18,27,40,60,90] 与每级步长全部是编译期常量，经 SimTuning 投影给客户端显示；局中没有任何一方（房主/服务器/玩家）能改曲线。
2. **per-robot 派生属性可成长**：maxHP/maxEnergy/移速/盾承伤/伤害从包级常量改为按升级等级派生；等级为零时与旧常量严格相等。
3. **购买与惩罚都是可回放的确定性事件**：购买走排队控制 API（与 AssistToggle 同族，ControlRecord 落录像）；core 拾取奖励与阵亡散落（PointDrop）在 tick 管线内由已记录状态推导，不引入墙钟或 goroutine。SimulationVersion 递增到 5，旧录像不含升级记录、数值等价。
4. **赏金惩罚只动存量**：阵亡最多掉 1 级 + 全部自由点数，掉落物是零和转移（只给点数不给计分），不创造点数、不改变 core 的计分语义。

## 放弃的方案

- **真盾条（护盾血槽）重设计**：与能量耗能模型叠成双资源，复杂度不成比例；采用降低盾下承伤系数表达「盾量」。
- **掉落复用 core 实体**：core 拾取带计分语义，混用会污染分数经济；新设 PointDrop 只给点数。
- **能量轨加回复**：回复 10→20 m/s 会与开火耗能 20/s 打平，达成无限持续火力。
- **跨局/永久成长**：v0.3 设计基准的「不做清单」继续对 meta 成长生效；本 ADR 只裁决局内成长。
