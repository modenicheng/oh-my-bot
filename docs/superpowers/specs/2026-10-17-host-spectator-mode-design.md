# 房主观战模式与结算页开下一局设计

日期：2026-10-17

## 目标

支持房主以观战模式创建房间。房主仍保留房主控制权限，但不生成自己的参赛机器人；正式局开始后，房主进入现有的全图只读观战画面。正式局至少要有一个真人参赛者或一个已配置的自动 Bot，空房不能开局。

结算页中，普通房主和观战主持人都可以直接开启下一局。观战主持人点击后仍留在房间控制会话中，收到新局地图后进入观战视图；普通玩家的既有结算和下一局流程保持不变。

## 语义与边界

- “观战模式开房”是房主身份的房间创建属性，不是现有 `SpectateRoom` 只读连接的别名。
- 观战主持人占用房主控制身份，但不进入 `Room` 的玩家成员、身份恢复表或当前 `Match` 的机器人花名册。
- 观战主持人可以执行房主动作：热身、开始正式局、切换 Bot、暂停、继续、提前结算和开启下一局。
- 观战主持人不能发送玩家输入、聊天、脚本、升级或其他玩家专属操作；客户端不显示玩家专属 HUD 和工作台。
- 首次创建窗口由首个 Join 的 `spectator_mode` 决定。房间创建后，后续 Join 的该字段被忽略，不能改变房间模式。
- 普通玩家加入观战房后仍是正常参赛玩家，并加入下一次正式局的机器人花名册。
- 观战主持人所在的房间不能仅凭主持人开局。开局名单中至少要有一个真人玩家或一个自动 Bot；服务端拒绝是最终约束。
- 观战主持人断线重连时，必须恢复同一个房主控制身份和观战模式，不得创建机器人，也不得被普通玩家的进房连接夺走。
- 结算页的“开始下一局”只能发送已有的 `START` 房间动作；服务端状态机仍负责权限、状态和参赛者校验。

## 架构

### 协议

在 `JoinRoom` 增加可选 `spectator_mode` 字段。该字段只表达首次建房意图；服务端将最终模式写入房间状态。`EvRoomState` 增加房主观战模式的只读状态，使客户端无需根据本地表单猜测当前房间语义。

不扩展 `SpectateRoom`，也不允许只读 spectator 连接执行房主动作。现有 live spectator 的安全边界继续保持：不进入玩家成员、不领取房主、不发送控制命令。

### 服务端房间与对局

- `Room` 保存 `hostSpectator` 创建属性，并在首次 Join 的创建窗口设置。
- `Room` 的成员数、房主昵称、累计积分仍只统计真人玩家；观战主持人不加入这些集合。
- `RoomConn` 保存观战主持人的控制会话，与普通 player session 分离；控制路由检查该会话是否为房主。
- `prepareLaunchLocked` 接收实际参赛者快照和 Bot 配置。普通房间沿用现有成员快照；观战房间排除主持人，再追加已配置 Bot。
- 若最终参赛名单为空，所有会启动模拟的房主动作返回明确错误，不改变房间状态，也不启动异步装配。
- 观战主持人收到 `mapBootstrap`、全图快照、实时积分榜和结算事件，但快照不包含 `self`；普通玩家仍收到原有 AOI 和 `self`。
- 房间状态广播携带主持模式，普通玩家和现有外部 spectator 都能据此正确呈现房间状态。

### 客户端

- 加入表单增加“观战模式开房”开关，并把选择保存到 Join profile；普通加入者默认关闭。
- `RoomSession` 的玩家连接携带 `spectatorMode`，但连接仍使用 Join 握手，以保留房主权限和断线恢复身份。
- 大厅根据 `EvRoomState.hostSpectator` 显示房间模式；观战主持人保留房主操作，普通玩家只显示等待状态。
- `GameController` 增加只读观战状态：使用已有全图快照渲染，禁止输入、聊天、升级、脚本工作台和玩家 HUD；相机以全图/观战方式运行，不依赖 `world.self`。
- 结算页的下一局按钮由房间模式和当前用户是否为房主共同决定。按钮触发 `START`，不直接销毁连接或伪造本地状态；收到下一局 `mapBootstrap` 后由现有路由进入新局。
- 普通玩家结算仍显示“回到房间”，不改变现有输入和工作台流程。

## 错误处理

- 空参赛名单由服务端返回现有控制通知/兼容 `say` 错误路径，客户端在大厅显示“至少需要一名真人参赛者或自动 Bot”。
- 观战主持人无权操作、房间状态非法或启动失败继续沿用现有 `RoomAction` 错误和 `match launch failed` 路径。
- 观战主持人断线期间房间仍保留身份；服务端不因为主持人不在而自动创建或删除参赛机器人。
- 新字段对旧客户端保持 protobuf 向后兼容：旧客户端不发送该字段时按普通房间处理；旧服务端忽略新增字段时，客户端仍按其回传的房间状态工作。

## 测试

### 协议与服务端

- 双语言生成物包含 `JoinRoom.spectator_mode` 与 `EvRoomState.host_spectator`，旧消息缺省值保持兼容。
- 首次 Join 开启观战模式后，主持人不计入成员数、在线真人数、身份表和 Match roster；普通玩家仍能加入并参赛。
- 后续 Join 不能覆盖房间模式；主持人重连恢复房主控制身份。
- 观战房无真人、无 Bot 时，START/WARMUP/RESTART 均拒绝且不改变状态；配置 Bot 后可以启动。
- 观战主持人收到无 `self` 的全图快照和结算；普通玩家仍收到带 `self` 的玩家快照。
- 现有只读 `SpectateRoom` 仍不能执行房主动作。

### 客户端

- 加入表单和 profile 正确读写观战模式；普通模式回归测试保持通过。
- 大厅正确显示观战模式、房主按钮和空参赛者错误。
- 观战主持人开局后不发送输入，不显示玩家专属 HUD/工作台，并能正常收到结算。
- 观战主持人结算页点击“开始下一局”发送一次 START；普通玩家仍只能按原流程返回房间。
- `typecheck`、Vitest、client build、startup browser check，以及相关 Go package tests 通过。
